## 3\.1 replicationid 的作用

**replicationid **

**是主节点生成的，主节点启动的时候就会生成，还有从节点晋升成为主节点的时候**，即使是用一个主节点，每次重启，生成的 replication id 都是不同的，从节点和主节点建立了复制关系，就会从主节点这边获取到 replication id

> 当前讨论的都是一个主节点多个从节点的情况
> 
> 后面谈到 集群 的时候，就是多个主节点，多个从节点了
> 
> 

info replication 获取到当前 replication id 的值

![Image](https://internal-api-drive-stream.feishu.cn/space/api/box/stream/download/authcode/?code=NGEzNzg4MWE1MWI0YmE2MjNmNzg2YWViNjZiZTUwMDRfYjhiMmUxOTdlOTBjNWI4YTExNzQ4OGZjNWUyOGJkNWZfSUQ6NzY2OTk4OTIyMjc1MzkxNDEyMV8xNzg2MjcwMTY3OjE3ODYzNTY1NjdfVjM)

那为什么有两个呢，一个replid1，一个replid2，一般情况下，replid2 这个是用不上的

但是比如，有一个主节点 A，还有一个从节点 B

主节点生成 replid，B 就可以获取到 A 的 replid

如果 A 和 B 通信过程中出现了一些网络抖动，B 可能就认为 A 挂了

B 就会自己成为主节点（给自己生成一个 replid）

此时，B 也会记得，之前旧的 replid，就是通过 replid2

后续网络稳定了，B 还可以根据 replid2 重新回到 A 的怀抱，这个需要手动干预，或者是哨兵机制可以自动完成这个过程

![Image](https://internal-api-drive-stream.feishu.cn/space/api/box/stream/download/authcode/?code=ZGJmNDJkZmI5MGNkZjU4NDk3OTRjNGZmMTdlZjc3OWFfMjc2N2I0MWFjOTQ4MGMyMTNjN2JmZWI0OGE5NjY2OGFfSUQ6NzY2OTk5MDUzMzg0Njc5NzI1N18xNzg2MjcwMTY3OjE3ODYzNTY1NjdfVjM)

## 3\.2 Offset 的作用

偏移量，主节点和从节点上都会维护 偏移量（整数），主节点的偏移量，主节点上会收到很多的修改的操作的命令，每个命令都要占据几个字节

主节点会把这些修改命令，每个命令的字节数进行累加

从节点的偏移量，就描述了，现在从节点这里数据同步到哪里了

**如果从节点这边的偏移量和主节点的偏移量一样了，就是追上了**

![Image](https://internal-api-drive-stream.feishu.cn/space/api/box/stream/download/authcode/?code=YjdjNDQ2YWNkOWVmM2YwYTdiMzc5MmFkZWY5ZjViZThfMGU2NzEzZDY5OGUxNGFiMmZkNWQxMGE2Yjc5MDdhMGNfSUQ6NzY2OTk5MjQ4NzcxMDU5MjIxOF8xNzg2MjcwMTY3OjE3ODYzNTY1NjdfVjM)

**replicationid 和 offset 共同描述了一个 “数据结合”**

**如果发现两个机器，replication id 一样，offset 也一样，就可以认为这两个 redis 机器上存储的数据就是完全一样的**



![Image](https://internal-api-drive-stream.feishu.cn/space/api/box/stream/download/authcode/?code=OWZhN2MzNWMxZTE0YmNhZWVkN2FlN2IyMmQ4MDc1ZWJfOTVlZmQ1NjI2MTlkYmIxMGM1NGQyYmZjYTBlNGJiMjFfSUQ6NzY2OTk5MzU1MDk4NTIxOTAzMF8xNzg2MjcwMTY3OjE3ODYzNTY1NjdfVjM)

psync这里可以从主节点获取全量数据，也可以获取一部分数据，主要就是看 offset 这里的进度

- offset 写作 \-1，就是获全量数据

- Offset 写具体的正整数，则是从当前偏移量位置来进行获取



# 四\. 全量复制 \&\& 部分复制 \&\& 实时复制

## 4\.1 全量复制和部分复制

获取所有数据是最稳妥的，但是会比较低效

如果从节点之前已经从主节点这里复制过来一部分数据了，就只需要把新的之前没复制过的数据搞过来即可

不要从节点索要那部分，主节点就一定给哪部分，主接待会自行判定，看当前是否方便给部分数据，不方便就只能给全量了。

**啥时候进行全量复制**

1. 首次和主节点进行数据同步

2. 主节点不方便进行部分复制的时候



**啥时候进行部分复制**

从节点之前已经从主节点上复制过数据了，因为网络抖动或者从节点重启了，从节点需要重新从主节点这边同步数据，此时看能不能只同步一小部分（大部分数据是一致的）

## 4\.3 全量复制的无硬盘模式

主节点在进行复制的时候，也支持 “无硬盘模式” \(diskless\)，其实也就是主节点，生成的 rdb的二进制数据，不是直接保存到文件中了，而是直接进行网络传输了（省下了一系列读硬盘和写硬盘的操作）

从节点，之前，也是先把收到的 rdb 数据，写入到硬盘中，然后再加载，现在也可以省略这个过程，直接把收到的数据进行加载了

即使引入了硬盘模式，仍然整个操作是比较重量，比较耗时的，网络传输（大规模数据，因为我们这个说的是全量复制），是没法省的

相比于网络传输来说，读写硬盘是小头

## 4\.5 部分复制的流程

从节点要从主节点这里进行全量复制，全量复制开销是很大的，有些时候，从节点本身已经持有了主节点的绝大部分数据，这个时候，就不太毒药进行全量复制了了

比如，出现网络抖动，主节点这边最近修改的数据可能就无法及时同步过来了，更严重的，从节点已经感知不到主节点了（进一步从节点可能会升级成主节点）

网络抖动一般都是 “暂时的”，过一会就恢复了，此时就可以让从节点和主节点重新建立联系

当从节点和主节点重新建立连接之后，就需要进行数据同步



psync带有具体的 replid 和 offset 值，主节点就要根据 psync 的参数进行判定，当前这次是按照全量复制合适还是部分复制合适

## 4\.6 实时复制的流程

- **全量复制**：从节点刚连上主节点之后，进行的数据初始化工作

- **部分复制**：全量复制的特殊情况，优化手段，目的和全量复制一样

- **实时复制**：从节点，已经和主节点，同步好了数据了（从节点这一时刻已经和主节点数据一致了）但是之后，主节点这边会源源不断的收到新的修改数据的请求，主节点上的数据就会随之改变，也需要能够同步给从节点

从节点和主节点之间会建立 TCP 的长连接

然后主节点把自己收到的修改数据的请求，通过上述连接，发给从节点（这个过程也是需要时间的，正常来说，这个延时是比较短的，但是如果是多级从节点的树形结构，这里的从节点的级别很多，有很多层，这个延时就会上升），从节点再根据这些修改请求，修改内存中的数据

在进行实时复制的时候，需要保证连接属于可用状态，需要心跳包机制

**主节点**：默认，每隔 10s 给从节点发送一个 ping 命令，从节点收到就返回 pong（默认阈值是 60s，没收到就默认从节点下线）

**从节点**：默认，每隔 1s 给主节点发起一个特定的请求，就会上报当前从节点复制数据的进度（offset）

这三个 redis server 里面的数据是不一定一样的

之前最开始创建从节点的配置文件，没有改这个地方，就导致了，生成 aof 文件的路径/文件名都是同一个

从节点是通过手动启动的方式运行的，此时 root 用户下启动 redis 服务器，于是生成的 aof 文件也就是 root 用户的文件

通过 service redis\-server start 启动的 redis 服务器（主要是怕，通过 root 启动 redis，权限太高，一旦 redis 被黑客攻破了，后果就会比较严重），是通过一个 redis 这样的用户，来启动的（所属的用户是 redis 用户）

![Image](https://internal-api-drive-stream.feishu.cn/space/api/box/stream/download/authcode/?code=M2YyZTQzZjc1OTBkNTEwNDQ5ODk3MTE0OGM0ODMzMTFfNzRhYzk1OTI5NWY0Y2NiZjczMGY0N2M0OWE5OWRjMjVfSUQ6NzY3MDA2MDIyMzYzODQwODQ4M18xNzg2MjcwMTY3OjE3ODYzNTY1NjdfVjM)

redis server 需要按照可读可写的方式打开这个 aof 文件，而这个文件对于 root 之外的用户只有读权限

因此 service redis\-server start 启动的 redis 服务器无法打开这个文件，就启动失败了

> **解决方案**：把三个 redis 服务器的生成的文件，也给区分开，更靠谱的是，直接把三个 redis 服务器的工作目录区分开（修改配置文件中的 dir 选项）
